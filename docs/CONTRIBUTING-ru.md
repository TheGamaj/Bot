# Участие в разработке Gamaj Bot

Спасибо за помощь. В проекте действует небольшой набор обязательных правил; прочитайте их до написания кода — pull request, нарушающий их, не будет принят.

## Красные линии

1. **Только имя Gamaj.** Никаких упоминаний других ботов или панельных проектов в коде, комментариях, текстах интерфейса, документации или ресурсах. Автоматический guard по именам окружений роняет сборку, если такое имя появляется.
2. **Никаких следов агентов.** Не упоминайте ИИ-ассистентов, агентов или инструменты автоматизации в коде, сообщениях коммитов или документации. Коммиты должны выглядеть как обычная работа разработчика.
3. **Один путь установки: нативный бинарник + systemd.** Никакого Docker и переключателя режимов установки. Установщик `scripts/install.sh` ожидает собранный бинарник `gamajbot` и настраивает systemd-сервис `gamaj-bot`.
4. **Каждая переменная окружения начинается с `GAMAJ_`.** Конфигурация рантайма живёт в JSON-файле (`panel_url`, `api_key`, `bot_token`, `admin_id`), а не в свободных переменных окружения; всё, что читается из окружения процесса, должно проходить naming guard.
5. **Секреты никогда не попадают в репозиторий.** Установщик создаёт конфиг с заглушками и `chmod 600`; сохраняйте это состояние.
6. **Документация самодостаточна.** Документация не должна отправлять читателя на GitHub или другой сайт «за подробностями»; контент находится в этом репозитории (и на сайте `Web/`).

## Процесс работы

1. Форкните или создайте ветку от `Asli`.
2. Держите изменения сфокусированными; одна тема на pull request.
3. Запускайте проверки, относящиеся к вашим правкам:

```bash
cd Bot
gofmt -l .                       # без вывода
go build ./... && go vet ./...
go test ./internal/platform/envguard/

# если меняли установщик:
bash -n scripts/install.sh scripts/manage.sh
```

## Сообщения коммитов

Короткие, в повелительном наклонении, о сути изменения, например:

```
Reject webhook updates with an unknown secret
Rate-limit admin commands per chat
```

Не добавляйте подписи инструментов, строки вида generated-by или co-author-трейлеры. Автор и коммитер должны быть вашим собственным Git-идентификатором.

## Стиль кода

- Go: `gofmt`, `go vet`, оборачивание ошибок через `%w`, табличные тесты рядом с пакетом, который они покрывают.
- Shell: `set -euo pipefail`, никаких внешних зависимостей помимо обычных POSIX-утилит.
- Telegram UX: строки для пользователей совпадают с формулировками дашборда панели; раскладки клавиатур должны работать и на узких, и на широких экранах.

## Сообщение о проблемах

Указывайте: версию бота (тег релиза или `gamajbot -version`), ОС и архитектуру, вывод журнала (`journalctl -u gamaj-bot -n 100`) и минимальные шаги воспроизведения. Никогда не вставляйте в issue реальные токены бота, ключи API или ID чатов — отзовите токен и приложите обезличенные логи. Вопросы безопасности передавайте мейнтейнерам приватно.
